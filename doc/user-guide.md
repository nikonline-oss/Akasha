# Akasha — User Guide (для владельца)

Akasha — твоё личное хранилище контекста: заметки, решения, источники, сниппеты о тебе и проектах. AI-агенты читают его, но меняют только через твоё одобрение.

## 1. Первый запуск

**Server:** открой `https://твой-хост/` → войди email+паролем из ENV (см. deployment.md).
**Portable:** запусти `akasha portable` → браузер на `http://localhost:5077`, логина нет (ты единственный пользователь машины).

Сразу сделай:
1. **Settings → Projects → New** — заведи первый проект (slug, описание, стек).
2. **Agents → New agent** — дай имя (например «Claude»), выбери скоупы (`read`+`propose`), скопируй ключ `ak_...` — он показывается **один раз**. Вставь в MCP-конфиг клиента.
3. При необходимости — **Secrets → New** (API-ключи, пароли; агенты их не увидят никогда).

## 2. Экраны UI

| Экран | Что делать |
|---|---|
| **Dashboard** | сводка: проекты, последние записи, pending proposals, активность агентов |
| **Projects** | список/карточки; внутри — записи проекта, связи, секреты проекта |
| **Entries** | поиск по типу (note/decision/source/comment/snippet), редактор Markdown с preview, теги, связи (`@entry` или кнопка Link) |
| **Search** | строка + режим hybrid/fts/semantic; результаты подсвечивают совпадения |
| **Approvals** | очередь proposals: слева diff (что изменится), справа кнопки Approve / Reject (+комментарент агенту); batch-approve для однотипных |
| **Scripts** | список скриптов, запуск с формой параметров (из params_schema), конструктор (пошаговый builder вместо JSON) |
| **Graph** | визуализация связей entries (mentions/relates/supersedes), фильтр по проекту |
| **Agents** | ключи, скоупы, last used; revoke одним кликом |
| **Audit** | журнал: кто/что/когда; фильтры по агенту и действию |
| **Settings** | профиль, master key статус, экспорт/импорт, sync-настройки (portable) |

## 3. Рабочий день с агентами

Ты пишешь в Claude/Cursor: *«помни, что мы решили использовать Redis для очереди»* →
агент вызывает `akasha_propose` → ты получаешь push от Telegram-бота (если настроен) с кратким diff →
кнопка **✅ Approve** — решение зафиксировано в vault. Утром открываешь Approvals для подробных случаев.

Мусорные предложения отклоняй с комментарием — агент видит статус через `akasha_get_proposal_status`.

## 4. Скрипты вместо ручных выборок

Пример задачи: «показывать все решения последних двух недель». Создай скрипт в конструкторе
(from=entries, kind=decision, created_at ≥ -14d) — сохрани как `recent-decisions`. Дальше:
- в UI Scripts → Run;
- агент зовёт `akasha_run_script {slug:"recent-decisions"}` и получает готовый ответ;
- правки скрипта сам агент может только предложить (`akasha_propose_script`).

Кэш: повторный запуск без изменения данных мгновенный; «Invalidate» — если нужен свежий взгляд.

## 5. Portable + сервер вместе

На ноутбуке — portable (работает в самолёте). Перед вылетом и после: `akasha sync`.
Конфликты (правил одно и то же с двух мест) превращаются в conflict-proposal — выбираешь версию руками.
Секреты живут отдельно на каждом устройстве и **не синхронизируются** — это фича.

## 6. Бэкап

Раз в неделю: Settings → **Export** (zip). Формат открытый: JSON + Markdown, читается любым редактором.
Импорт в новую установку идемпотентен — можно восстанавливаться поверх частичных данных.

## 7. Частые вопросы

- **Агент видит секреты?** Нет: физически исключены из query/MCP/sync.
- **Агент может удалить запись?** Нет: delete тоже только proposal + твой approve.
- **Потерял ключ агента?** Re-issue (новый ключ), старый revoke.
- **Что в audit?** Все чтения агентами (query/search/run), все mutation, reveal секретов, sync.
- **Онлайн обязателен?** Portable — полностью офлайн; server требует сеть только для синка и агентов.
