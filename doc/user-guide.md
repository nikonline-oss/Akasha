# Akasha — User Guide (для владельца)

Akasha — твоё личное хранилище контекста: заметки, решения, источники, сниппеты о тебе и проектах.
AI-агенты читают его, но меняют только через твоё одобрение (proposals).

## 1. Первый запуск

**Server:** открой `https://твой-хост/` → попадёшь на страницу входа **/login** → email + пароль из `.env`
(см. [deployment.md](deployment.md)). Пока не вошёл — API, MCP и весь UI закрыты (401 / редирект на вход).

**Portable:** запусти `akasha portable` → браузер откроется сам на `http://127.0.0.1:5173`. Логина нет —
ты единственный пользователь машины, доступ только с localhost.

Сразу сделай:

1. **Проекты → «Новый проект»** — заведи первый проект (название, описание, стек).
2. **Агенты → «Создать агента»** — имя (напр. «Claude»), скоупы `read`+`propose`, скопируй ключ `ak_…`
   (показывается **один раз**) и вставь в MCP-конфиг клиента.
3. При необходимости — **Секреты → «Добавить»** (API-ключи, пароли; агенты их не увидят никогда).

## 2. Навигация

Слева — выдвижное меню: **Дашборд · Проекты · Поиск · Граф · Апрувы · Скрипты · Агенты · Секреты · Синхронизация · Аудит**.
В шапке — кнопка **«Новая запись»** и **«Выйти»**.

## 3. Экраны UI

| Экран | Что делать |
|---|---|
| **Дашборд** | сводка: быстрые действия, проекты, последние записи, счётчик pending-апрувов |
| **Проекты** | список/карточки; кнопка «Новый проект» (название/описание/стек); ссылка на записи проекта |
| **Запись** (`/entries`, `/entries/{id}`) | создание/редактирование: заголовок, тип (note/decision/source/comment/snippet), проект, теги, тело Markdown; «Удалить» у существующей |
| **Поиск** | строка запроса + фильтр по типу; гибридный FTS+семантика, результаты со сниппетами |
| **Граф** | узлы-записи, рёбра-связи (mentions/supersedes/contradicts/derived_from); клик по узлу открывает запись |
| **Апрувы** | очередь proposals: diff (что изменится) + Approve / Reject (комментарий обязателен) |
| **Скрипты** | список скриптов, запуск; результат таблицей/JSON |
| **Агенты** | создание ключей, скоупы, last used; Revoke одним кликом; новый ключ показывается один раз |
| **Секреты** | добавить (шифруется AES-GCM), «Показать» (расшифровка + «Копировать»), удалить |
| **Синхронизация** | (portable) URL сервера + ключ устройства + ID; «Синхронизировать» → результат и время последней синхронизации |
| **Аудит** | журнал кто/что/когда; фильтры по actor и action |

## 4. Рабочий день с агентами

Ты пишешь в Claude/Cursor: *«помни, что мы решили использовать Redis для очереди»* →
агент вызывает `akasha_propose` → ты получаешь push от Telegram-бота (если настроен) с кратким diff →
кнопка **✅ Approve** — решение зафиксировано. Утром открываешь **Апрувы** для подробных случаев.

Мусорные предложения отклоняй с комментарием — агент увидит причину через `akasha_get_proposal_status`.

## 5. Скрипты вместо ручных выборок

Пример: «показывать все решения последних двух недель». Создай скрипт (structured JSON Query:
`from=entries`, `kind=decision`, `updated_at ≥ -14d`) → сохрани как `recent-decisions`. Дальше:

- в UI **Скрипты → Запустить**;
- агент зовёт `akasha_run_script {slug:"recent-decisions"}`;
- правки скрипта агент может только предложить (`akasha_propose_script`).

Кэш инвалидируется по `version` + `data_version`; повторный запуск без изменений мгновенный.

## 6. Portable + сервер вместе

На ноутбуке — portable (работает в самолёте). Перед вылетом и после открой **Синхронизация → Синхронизировать**
(или `akasha sync` в CLI). Конфликты (правил одно и то же с двух мест) превращаются в conflict-proposal —
решаешь версию руками. Секреты живут отдельно на каждом устройстве и **не синхронизируются** — это фича.

## 7. Бэкап

Раз в неделю: `akasha export backup.zip --secrets` (или экспорт в UI). Формат открытый: JSON + Markdown.
Импорт идемпотентен (`akasha import backup.zip`) — можно восстанавливаться поверх частичных данных.

## 8. Частые вопросы

- **Агент видит секреты?** Нет: физически исключены из query/MCP/sync.
- **Агент может удалить запись?** Нет: delete — тоже proposal + твой approve.
- **Потерял ключ агента?** Создай новый, старый Revoke.
- **Что в аудите?** Чтения агентами (query/search/run), все mutation, approve/reject, reveal секретов, sync.
- **Онлайн обязателен?** Portable — полностью офлайн; server требует сеть только для синка и агентов.
